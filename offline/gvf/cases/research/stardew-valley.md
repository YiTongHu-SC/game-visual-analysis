# 星露谷物语：三张官方 Steam 截图对 GVF 的检验

观察日期：2026-10-21。样本限定 Steam App 413150 商店图库索引 0、1、2；三图均已实际打开检查。它们是官方发布的游戏内画面资料，**本次没有启动游戏或录制运行过程**。图像构建版本、拍摄日期、UI 隐藏方式及商店处理过程未知，不能把 URL 的缓存时间戳当作拍摄日期。

结论是：这组画面同时具有较高的具象可辨识性、明显简化的人物结构、密集的表面像素信息和强烈的场景明暗差异。“像素”只描述外观还不够；它既不能替代形体、空间与信息层级，也不能证明原生像素倍率或真实制作管线。

## 十二域拆解

| 域 | 可从三图共同表达的观察 | 区间／证据与限制 |
| --- | --- | --- |
| 具象与表现 `representation` | 人、屋、栅栏、动物、植物可辨；像素外观显著，形态经过删减；道路、遮挡与栅栏形成常规空间组织 | 可辨识性以字典 75–100 档为初步区间；“像素外观”不等于已经证明底层 2D 资产系统，`mode` 保持 unknown |
| 形体 `form` | 人体以较少部位和较大的头／帽轮廓表达；建筑矩形与有机树冠共存 | 自然度粗分 25–50；没有尺度表，不给比例夸张和尺寸一致度伪精确分数 |
| 线条 `line` | 深色外轮廓与屋板、窗、栅栏等内结构边界共同组织物体；线色会随对象改变 | `outer_and_inner`、`tinted_dark` 适合描述当前样本；未测量法向宽度，不填 1 px／3 px 等猜测 |
| 表面 `surface` | 木板、屋瓦、草丛、土点等信息密集，像素块并非随机电影颗粒 | 细节 50–75、笔触可见性 0–25 为未校准视觉区间；纹理制作来源、PBR 输入和材质多光照响应 unknown |
| 颜色 `color` | 00／02 黄土、绿植和红棕建筑分工明显；01 大片暗色、局部暖灯与绿色生物形成不同关系 | 整体鲜艳感跨图约 25–75；不从 JPG 的不同 RGB 数量推出源色板数，不猜源 token 的 L/C/h |
| 明暗与光照 `light` | 昼景的局部块面、洞窟的连续亮暗衰减并存 | 外观记 `mixed`；不能把洞窟连续衰减直接标成 PBR，也不能因为部分像素有分段色就把整作叫 cel shader |
| 相机 `camera` | 可同时看见屋顶、地面及立面，属 `elevated_oblique` 的可见方向 | 常用“俯视像素”在这里不是严格正俯视；透视／正交、FOV、准确角度、米制距离和相机移动全部 unknown |
| 构图 `composition` | 重复行列、栅栏与路径将信息分组；主角没有无条件压倒环境的面积／亮度优势 | 农场比洞窟存在更多竞争性细节；焦点与主体分离度约 50–75，仅为看图判断，不是限时识别测试结果 |
| 运动 `motion` | 01 是动作中的一个姿态，02 两个人姿态不同 | 不能从单张动作姿态推自然度、更新率、前摇或挤压拉伸；本域六项全部 unknown |
| 特效 `vfx` | 01 的白弧和浮字、灯周围可见软亮部；00／02 没有同样突出的挥击反馈 | 空间占据较低，不知道时长、峰值叠加、闪烁频率、模糊快门或震屏幅度；不将“此帧没看到”写成永久关闭 |
| 界面 `ui` | 01 黄色“5”是贴近世界对象的可见信息，00 邮箱上有信件图样；未展示完整常驻 HUD | 可描述样本的空间标记，但无法证明整套 UI 只用一种承载方式；没有菜单／字号样本不应标 N/A |
| 显示处理 `presentation` | 阶梯状轮廓和细碎色块可见 | JPG 经压缩、可能经过缩放，不能证明 nearest、整数放大倍率、逻辑像素网格或内部目标分辨率；颗粒与色差也不靠印象填数 |

`vfx.density`按0.2收窄后的静态空间语义解释：以完整画面比较占据范围和同时可见叠层；ROI只定位证据，不把框内占比当成全帧占比。原粗区间保留但未重新校准，不表示发生频率、持续时间或动态峰值。

## 这次检验暴露的框架问题

1. **可辨识性与写实必须分开。** 这组人物虽非自然比例，仍很容易被识别为穿帽人物；树、屋和动物也有稳定具象指涉。把“像素”直接转成低 recognizability 会误导 AI。
2. **一个整体鲜艳感或明暗分不覆盖场景变体。** 日景与洞窟共享许多造型和边缘规则，却在颜色分布上差异明显。观察记录需要保留图像／对象范围；宽区间只用于诚实暴露差异，不能代替以后分别校准场景。
3. **“俯视”不应兼任相机矩阵和观看方向。** 新增 `camera.view_orientation` 能接住这里的外观；`camera.projection` 继续留给源工程或充分制作资料。
4. **像素美术的可见栅格与原始像素倍率不是一回事。** 可以分析最终 JPG 的边缘结构；没有无损源图和原生规格，就不把 2×／3× 等倍数写成事实。
5. **时间字段大量 unknown 是有效结论。** 当前样本适合验证静态术语覆盖面，无法校准动画和交互节奏。用默认 60 fps 或根据挥击弧猜时长，会把观察变成虚构的生产规范。
6. **框架需区分局部可见信息与完整 UI 覆盖。** 一帧浮字足以否定“完全无 UI”，却不足以描述整个菜单系统；缺样本应为 unknown，而不是 N/A。

本案不会自动生成仿制该游戏的生产 profile。将观察转为新游戏设计时，应另选目标、允许差异、参考用途和制作约束；图像观察的置信度也不能替代项目校准。
